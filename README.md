## 🧠 Method (honest disclosure)

Everything in this repo was generated by **heuristics over GitHub metadata**, **without a real LLM call**:

- `summary` — echoes the repo description
- `features` / `capabilities` — splits description on commas / semicolons
- `use_cases` — defaults to `["research", "explore", "evaluate"]`
- `tech_stack` — inferred from `language` + `topics` only
- `value_score` — `log(stars) + topics_count × 0.3`, range 5–9.3
- **Similar repos** — **Jaccard** over tags/topics; limited discrimination

> Bottom line: **good enough for inventory, not yet strong enough for decisions.**

## 🚀 Upgrade to real LLM analysis

Want a deeper pass? Configure [`github-stars-analyzer`](https://github.com/csxo/github-stars-analyzer):

```env
GITHUB_TOKEN=<fine-grained-token-with-public_repo>   # bumps quota to 5000/h
LLM_API_KEY=<DeepSeek / OpenAI / any OpenAI-compatible provider>
```

```bash
gsa sync --user csxo                           # re-fetch READMEs
gsa analyze --provider openai_compatible \
            --model deepseek-chat              # real LLM analysis
gsa report                                      # regenerate Markdown (overwrites)
```

After that:

- `summary` becomes a real README-based summary
- `features` / `capabilities` / `use_cases` are read-out, not split-out
- `value_score` is judged, not derived from `log(stars)`
- Similar-repos can be upgraded to embedding-based similarity

## ⚠️ Caveats

- Content only refreshes when **this repo itself is rebuilt**; new stars on csxo don't flow in automatically.
- No real README reads → limited summarization depth (see upgrade path above).
- Jaccard similarity has weak discrimination on long-tail projects.
- Rankings are based on `stars` + topic count, not actual quality.
